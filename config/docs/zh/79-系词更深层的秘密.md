# **79. 系词更深层的秘密** 

[**破解所有日语句子的三分之一！系词更深层的秘密。+Tae Kim 的谬误 | 第 79 课**](https://www.youtube.com/watch?v=euHYPcMoao4&list=PLg9uYxuZf8x_A-vcqqyOFZu06WlhnypWj&index=81&ab_channel=OrganicJapanesewithCureDolly)

こんにちは。

今天我们要讲一个对日语核心结构绝对至关重要的东西。我们最近在谈到 Tae Kim 先生以及他扰乱我们对这个东西的理解的方式时，讲过它。它就是系词（copula），它实际上支配着我们在语言本身里能说、能沟通的极多内容。它对我们如何概念化世界至关重要。

![](../media/image145.webp)

现在，Tae Kim 其实从来不用那个 C 开头的词 <code>copula</code>（系词），而这正是问题的一大部分。但有些人也许问的不是 Tae Kim 为什么不用，而是我为什么用。毕竟，我尽可能避免使用技术性的语言学和语法术语。

我不常使用 <code>**grammatical subject**</code>（语法主语）这个词；我更少使用 <code>**predicate**</code>（谓语）这个词。**我更愿意说 <code>A-car</code> 和 <code>B-engine</code>。**

![](../media/image939.webp)

这样我们大家都知道彼此在说什么。那我为什么要用 <code>copula</code> 这个抽象又相当可怕的词呢？

## 什么是“系词”

嗯，原因是英语没有专门的系词，所以对英语母语者来说，要准确抓住系词到底是什么可能相当困难。我必须把那个功能作为一个独立的东西来介绍。当 Tae Kim 谈到系词性表达时，他把它们称为 <code>state-of-being</code>（存在状态）表达，而这正是整个问题的关键。

那么，系词是什么，为什么英语没有专门的系词，又为什么它这么重要？我们就从 <code>what is a copula?</code>（系词是什么？）开始。

给系词下定义最简单的方式是：**它就是一个单向的等号**。

![](../media/image1138.webp)

**它告诉我们 A 是 B**，**尽管 B 不一定是 A**。所以，<code>さくらは日本人**です**</code>。*（显然，だ 也一样）*樱**是**一个日本人；**一个日本人不一定是樱。**

现在，这是简单的解释。但如果我们再深入一点，**系词实际做的是把事物放进集合里**。

<code>さくらは日本人**です**</code> **意思是樱属于 <code>Japanese person</code>（日本人）这个集合**。

![](../media/image704.webp)

而这对于语言来说是根本重要的，语言是人类用来概念化世界——他们周围看到的事物、可见可感的宇宙——的工具。把事物放进类别，是我们处理它们最根本的方式。**一朵玫瑰属于 <code>flower</code>（花）这个集合**。

**花属于 <code>growing things</code>（生长之物）这个集合**。**生长之物属于 <code>living things</code>（生物）这个集合**。**生物属于 <code>things</code>（事物）这个集合**。

我们无时无刻不在把事物放进集合里，这就是我们概念化它们的方式。如果我们不能把事物放进集合里，我们对任何东西都说不了什么。

所以**从根本上说，这就是系词所做的事**。**它给了我们一种非常简单、直接、不啰嗦的方式，随时把任何东西放进一个集合，随时界定某物所属的集合。**

---

**现在，这个集合可能只是一个元素的集合。在这种情况下，等号是双向的。** 所以，比如，如果我说 <code>That person over there is Sakura</code>，那么那边那个特定的人和樱是同一个人。

**樱是一个只包含一个元素的集合，那边那个人、而且只有那边那个人，属于它。** **至少，是这一个樱。** **我们说的显然不是所有叫樱的人**。

所以这就是系词所做的事。为什么围绕它有这么多困惑？它不是一个相对简单的功能吗？嗯，是的，它是一个简单的功能。

这里的主要问题，就像西方对日语的误解常常那样，并不在日语里，而在英语本身的性质里。**英语，正如我所说，没有专门的系词。**

**它确实有一个系词。每种语言都必定有一个系词。** 如果我们没有某个执行系词功能的东西，我们就根本无法把事物放进集合，这意味着我们概念化事物的能力会受到极大限制。

**所以英语所做的，是把存在动词和系词合并成一个。** **存在动词就是单纯告诉我们某物存在的东西。** **它有各种形式：<code>is / am / are / was</code> 等等。**

![](../media/image794.webp)

所以，如果我们说 <code>I **am** an American</code>，那就是**系词**在起作用。我们说的是**我属于叫作 <code>American people</code>（美国人）的那个集合**。如果我们说 <code>I think, therefore I am</code>，我们用的就是存在动词。

**我们并没有说任何关于我是什么、我属于哪个集合的话。** 我们只是说，因为我在思考，所以我们可以自信地断言我存在。

现在，由于英语没有两个分开的词来表达这两个概念，它其实并不会给英语母语者，或至少部分通过沉浸学习英语的外国学习者带来多少麻烦，因为过一阵子，一切都会通过使用和经验变得清晰；**但当英语试图去看那些有单独系词的语言时，它就确实会带来麻烦。** 日语显然是其中之一，西班牙语是另一个。

---

**西班牙语有两个系词，<code>ser</code> 和 <code>estar</code>**：<code>ser</code> 告诉我们某物所属的永久集合，<code>estar</code> 告诉我们某物所属的相对暂时的集合。这是大多数语言都不做的区分。

**但这里重要的区分是，<code>ser</code> 和 <code>estar</code> 与 <code>haber</code>（即存在动词）并不相同。**

![](../media/image985.webp)

所以如果我们说 <code>Estos **son** huevos</code>，我们说的是 <code>These **are** eggs</code>（这些是蛋）；*（这里的 “son” 应该是系词）*

![](../media/image1133.webp)

如果我们说 <code>**Hay** huevos</code>，我们说的是 <code>Eggs **exist**</code>（蛋存在）——两种完全不同的陈述。正如我所说，**在英语里我们不会把这两种陈述搞混，但当我们试图把英语的解释套用到那些系词和存在动词有不同词的语言上时，混乱往往随之而来。**

## だ 与 です 是同一个系词

现在，在我那期关于 Tae Kim 与系词的视频下评论的一些人，并没有完全被我的论点说服，即 <code>です</code> 和 <code>だ</code> 是同一个东西，因为 Tae Kim 那么强烈地主张它们不是。我想我把他们中的大多数都驳倒了。我没有驳倒所有，因为我并不想做到面面俱到。

![](../media/image1013.webp)

我在这里也不打算处理那些论点，因为我觉得它们是枝节问题。事实上，我会在不久的将来的一个视频里处理它们，**但这里的要点是：拿像 <code>だ isn't necessarily needed in this case but です is</code> 这样的论点，来支撑 <code>だ</code> 和 <code>です</code> 不是同一个东西这个更大的论点，是把整件事本末倒置、里外翻了个个儿。**

**重要的不是 <code>だ</code> 和 <code>です</code> 在这里或那里发挥的作用稍有不同，不是 <code>だ</code> 能在这里省略而 <code>です</code> 不能在那里省略，诸如此类。** 这些对于**它们两者都是系词**这个事实的问题来说，完全是枝节。

反对这个谬误的根本论点很简单：我们知道 **每种语言都需要有一个系词。** **没有系词功能，语言就绝对必须说的那些内容，你有一半都说不出来。** 你就没有一门真正的语言。

**如果你没有任何系词功能，你拥有的就是一门残缺的语言。** 现在，日语有时用 丁寧語（です/ます 体*＝礼貌语*）说话，有时用直白的普通日语说话。**其中一个是 <code>です</code>** *（礼貌）***；另一个的系词是 <code>だ</code>。** *（普通）*

现在，如果你要主张它们不是同一个东西，因此其中一个不是系词，那你就必须给出系词是什么，无论是普通语还是 丁寧語（です/ます 语），因为**这两者都必须有一个系词。** **没有系词你就没有语言**，所以如果你说它们不是同一个东西，你就有责任告诉我们，在这两种说法形式里系词到底在哪里。

当然，Tae Kim 从不处理这个问题，因为他似乎并不真正理解，存在一个系词，它与他所谓的 <code>the state of being</code>（存在状态）是两回事。

## 系词 vs 存在状态

现在，人们可能提出的另一件事是，他们也许会说：“嗯，英语用存在来充当系词，肯定不是偶然的巧合吧。这两者不是有点紧密相关吗？毕竟，**在日语系词更古老的形式里，比如 **である** 和 **でございます**，存在确实在起作用。**ある** 和 **ございます** 是存在类词，尽管 **で** 把它们变成了系词。**”

![](../media/image951.webp)

这个问题的答案绝对是“是”。其中的原因在于人类对本体论——也就是关于存在本身的科学或哲学——的感知。人类倾向于相信，一个事物所属的集合对它的存在是根本性的。

**在某种意义上，这当然是对的。** **我们通过某物所属的集合来定义它，而它作为它所在的那个存在（而非任何其他存在）的存在，从根本上与它所属的集合绑定在一起。** 一朵玫瑰属于 <code>flower</code>（花）这个集合。一旦我们知道这一点，我们就能对它做出各种各样的猜测。

我们也许不知道它确切长什么样，但我们可以说它大概有茎、有花瓣、有叶子、长在土里，等等等等。**所以，某物所属的集合，对它是作为那个特定的存在而不是另一个存在，是至关重要的。**

---

**但理解存在状态与某物被归属的集合在语义上相关，并不意味着我们应该把二者混为一谈。** 当我们说 <code>I **am** an American</code> 时，**我们用的 <code>am</code> 与说 <code>I think, therefore I **am**.</code> 时的意思并不相同。**

**如果我们相信日语系词（由 <code>だ</code> 或 <code>です</code> 表达）与存在状态（由 <code>いる</code> 或 <code>ある</code> 表达）其实是同一个东西，我们就白白丢掉了日语中一个根本重要的区分。** 当然，Tae Kim 先生并不这么认为，但与此同时，他在厘清这个区分到底是什么时又有很大困难，于是我们最后就会以为 <code>だ</code> 和 <code>です</code> 不是同一个东西。

**有少数几种情况，<code>だ</code> 可以被省略，有时是合乎语法的，有时是不合语法的，而这些情况不适用于 <code>です</code>**，这是真的，**但它们并不影响它们两者都是系词这个事实。**

## です 不作为系词发挥作用的一个例子

**有一种情况，<code>です</code> 被使用但并不作为系词发挥作用，那就是形容词的情况。** 正如我在上一期视频里演示的<sup>[[78]](./78-击穿核心-tae-kim-对比系词-基于日语结构的批判性评述.md)</sup>，**形容词是 <code>です</code> 被使用、却不是系词、只是一个空洞的正式** *（礼貌）* **标记的唯一情况。**

![](../media/image512.webp)

### 形容词里的 です 不只是个随意的礼貌标记

但这里还有另一点我们必须考虑，那就是：虽然在那样的情形下——也就是说，**在形容词的情况下、而不是其他任何情况下**（正如我在那期视频里演示的，它只发生在形容词的情况下）——**虽然在形容词的情况下，说 <code>です</code> 是一个空洞的正式标记是对的，但它并不只是一个随意的空洞正式标记。**

***正如我早先提到的，です / ます 更确切地说是礼貌标记，而不是正式标记。*** ***它们属于 丁寧語（礼貌语）。所以把它们称为礼貌标记反而更准确。***

如我们所知，**只有两种句子，A 是 B 句和 A 做 B 句**，而**在日语里有两种 A 是 B 句**，也就是**形容词句**、**它们在简单形式下必须以 -い 结尾**，以及**系词句**，它们**必须以 <code>だ</code> 或 <code>です</code> 结尾**。

![](../media/image90.webp)

::: info
 以防万一，[**这里**](https://japanese.stackexchange.com/questions/43244/why-cant-%e3%81%a0-be-used-after-an-i-adjective/43246#43246)和[**这里**](https://japanese.stackexchange.com/a/97338)：最好不要把 -い 误当成像 だ 那样严格意义上的系词，而应当把它看作形容词的述语性后缀，它本身就能结束一个句子。  
它表示“X 是／＝这个形容词性质”，例如这大概就是它本身承载系词功能的原因。  
这也是为什么 だ 不跟它一起使用，因为那会冗余，-い 已经基本暗示了它。  
Dolly 就是这么解释的——它自身承载系词功能，这大概也是 だ 不被使用的原因。

但围绕这个问题，你可以去搜一搜，会发现有不同的立场，有人把 -い 称为“某种系词”，有人不这么叫，有些人甚至质疑日语到底有没有形容词。  
但总的来说，叫它什么并不完全重要，重要的是你理解它在语言中如何运作、以及如何正确使用它。因为[**并不是所有以 -い 结尾的词都自动是形容词**](https://jisho.org/search/%E6%B4%97%E3%81%84)，因为可能有一个隐藏的汉字形式等等。尽管 98% 的情况下它确实是形容词。

基本上，Dolly 的作用是给你基础，如果你往深处钻，事情很少是直接而普适的。语言是一种非常复杂的构造，并不完全是那样运作的。  
比如说，这就是为什么有那么多学习它、解读它、解释它的方式。选择对你有用的那种。
:::

**所以，当我们把一个 <code>です</code> 放在形容词句末尾时，发生的是我们把系词功能加倍了。** 说 <code>さくらは**かわいい**です</code> 就像在说 <code>*(Speaking of)* Sakura *(she)* **is-cute** is</code>。说 <code>ペンが**赤い**です</code> 本质上就是在说 <code>Pen **is-red** is</code>。

我们在把那个系词功能加倍。**所以，虽然 <code>です</code> 是一个空洞的正式标记，但它并不只是一个随意的正式标记。** 它在做一件语言中有时会做的事，那就是*（它）***充当冗余**——**把同一件事说两遍。**

::: info
 我明白，既然它是冗余，我们可以说它并不是严格用来履行小句或句子的系词功能的系词，而它的主要重点在于：它给 -い 里的系词功能提供这种礼貌层面，以表明句子是礼貌的。
 :::

*它怎么说仍然是一个系词，但由于 -い 有类似的功能，它主要展示的是礼貌。*

**而这就是 <code>です</code> 做出与 <code>だ</code> 不同的事情的唯一实际情形。**
